## General workflow

1. **Fork** the repository on GitHub.
2. **Clone** your fork locally:
   ```bash
   git clone https://github.com/<your-username>/begginers-html-css-javaScript.git
   cd begginers-html-css-javaScript
   ```
3. **Install dependencies:**
   ```bash
   npm install
   ```
4. **Create a branch** following the [naming convention](#branch-naming):
   ```bash
   git checkout -b lesson/css-grid
   ```
5. **Make your changes** following the guidelines in this file.
6. **Verify all quality gates pass** (see [Code quality gates](#code-quality-gates)).
7. **Commit** using the [Conventional Commits](#commit-format) format.
8. **Push** to your fork and **open a Pull Request** against `main` using the PR template.

## Branch naming

```
<type>/<short-kebab-description>
```

Examples:

- `lesson/css-grid`
- `fix/lesson-quiz-reset`
- `docs/contributing-guide`
- `i18n/spanish`

Keep the description short (2–4 words), lowercase, hyphen-separated.

## Commit format

This project uses [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<optional scope>): <short description>
```

| Type       | When to use                              |
| ---------- | ---------------------------------------- |
| `lesson`   | Adding or updating a lesson              |
| `feat`     | Adding a new feature to the app          |
| `fix`      | Fixing a bug                             |
| `docs`     | Documentation only changes               |
| `refactor` | Code change that is not a fix or feature |
| `test`     | Adding or fixing tests                   |
| `chore`    | Tooling, config, dependencies            |
| `i18n`     | Translation or string changes            |

Examples:

```
lesson(css): add CSS Grid lesson with interactive demo
fix(quiz): reset selected answer when navigating lessons
docs: update README with project structure
chore: upgrade Vite to v6.4
```

The description must:

- Be in the imperative mood ("add", "fix", "update" — not "added", "fixes")
- Be lowercase
- Not end with a period
- Be 72 characters or fewer

## Code quality gates

Every PR must pass all four gates before it can be merged. Run them locally before pushing:

```bash
# 1. All tests pass
npm test

# 2. 100% coverage — no regressions allowed
npm run test:coverage

# 3. Zero lint errors
npm run lint

# 4. Formatting is consistent
npm run format:check
```

If `format:check` fails, run `npm run format` to auto-fix it, then commit the result.
If `lint` reports fixable errors, run `npm run lint:fix`, then commit the result.

These same checks run in CI on every PR. A PR with failing checks will not be reviewed.

## Adding a new lesson

This section is your step-by-step guide for a first contribution. Adding a lesson is the canonical entry point — it touches every meaningful layer of the codebase and gives you a complete picture of how the app works.

### The no-AI rule

> **All lesson content and code must be written by you, not generated by an AI tool.**

This applies to:

- The `content` string (the plain-English explanation)
- The `codeSnippet` string
- The quiz `question`, `options`, and `explanation` fields
- The demo component (`YourTopicDemo.tsx`)
- The test file (`YourTopicDemo.test.tsx`)

The goal of this project is for contributors to genuinely understand and be able to explain what they are teaching. AI-generated content defeats that purpose and will result in the PR being closed.

If you are unsure how to explain a concept in your own words, that is a signal you need to study it more before writing the lesson — and that is perfectly fine.

---

### Anatomy of a lesson

Every lesson entry in `src/data/lessons/lessons.tsx` has this shape:

```ts
"your-lesson-key": {
  category: "HTML" | "CSS" | "JS",       // Determines sidebar grouping and badge color
  title: "N. Short Title",               // Number prefix keeps lessons ordered
  icon: <IconComponent />,               // lucide-react icon
  color: "bg-X-50 border-X-200 text-X-800", // Tailwind classes matching the category
  content: "Plain-English explanation of the concept. ...",
  codeSnippet: "Minimal code example as a string. ...",
  demoTitle: "Label shown above the demo",
  demo: <YourTopicDemo />,              // Interactive React component
  questions: [                          // Exactly 2 per-lesson quiz questions
    {
      id: 201,                          // Unique integer — check existing IDs first
      topic: "html" | "css" | "js",
      question: "...",
      options: ["A", "B", "C", "D"],    // Always 4 options
      correctAnswer: 0,                 // Zero-based index of the correct option
      explanation: "Why this answer is correct. ...",
    },
    { id: 202, ... },
  ],
},
```

### Step-by-step walkthrough

#### Step 1 — Create a branch

```bash
git checkout -b lesson/your-topic-name
```

#### Step 2 — Create the demo component folder

```
src/components/demos/YourTopicDemo/
  YourTopicDemo.tsx      ← the interactive demo
  YourTopicDemo.test.tsx ← tests (100% coverage required)
  index.ts               ← barrel re-export
```

**`index.ts`** always looks like this:

```ts
export { YourTopicDemo } from "./YourTopicDemo";
```

**`YourTopicDemo.tsx`** must:

- Be a focused interactive demonstration of exactly one concept
- Use Tailwind classes for styling (no inline styles)
- Use `useTranslation` from `react-i18next` if it has any user-facing strings
- Import from path aliases (`@atoms/Button`, not `../../atoms/Button`)

Example minimal demo:

```tsx
import { useState } from "react";

export const CssGridDemo = () => {
  const [cols, setCols] = useState(3);

  return (
    <div>
      <label className="block mb-2 text-sm font-medium text-gray-700">Columns: {cols}</label>
      <input
        type="range"
        min={1}
        max={6}
        value={cols}
        onChange={(e) => setCols(Number(e.target.value))}
        className="w-full mb-4"
      />
      <div
        className="gap-2"
        style={{ display: "grid", gridTemplateColumns: `repeat(${cols}, 1fr)` }}
      >
        {Array.from({ length: cols * 2 }).map((_, i) => (
          <div key={i} className="bg-indigo-200 rounded p-4 text-center text-sm font-bold">
            {i + 1}
          </div>
        ))}
      </div>
    </div>
  );
};
```

**`YourTopicDemo.test.tsx`** must:

- Achieve 100% statement, branch, function, and line coverage
- Use `@testing-library/react` and `@testing-library/user-event`
- Test all interactive states and conditional branches
- Not rely on implementation details — test what the user sees

Example:

```tsx
import { describe, it, expect } from "vitest";
import { render, screen } from "@testing-library/react";
import userEvent from "@testing-library/user-event";

import { CssGridDemo } from ".";

describe("CssGridDemo", () => {
  it("renders the default 3-column grid", () => {
    render(<CssGridDemo />);
    expect(screen.getByText("Columns: 3")).toBeInTheDocument();
  });

  it("updates the column count when the slider changes", async () => {
    render(<CssGridDemo />);
    const slider = screen.getByRole("slider");
    await userEvent.type(slider, "{arrowRight}");
    expect(screen.getByText("Columns: 4")).toBeInTheDocument();
  });
});
```

#### Step 3 — Export from the demos barrel

Open `src/components/demos/index.ts` and add your export in alphabetical order:

```ts
export { CssGridDemo } from "./CssGridDemo";
// ... other exports
```

#### Step 4 — Add the lesson entry

Open `src/data/lessons/lessons.tsx` and add your entry to the `lessons` object. Keep the lessons in logical order (group by category, then by complexity within the category).

Import your demo at the top of the file with the other demo imports:

```ts
import { CssGridDemo } from "@demos";
```

#### Step 5 — Write quiz questions

Each lesson needs exactly **2 questions** in its `questions` array. Good quiz questions:

- Test **understanding**, not memorization — ask "what happens when..." not "what is the syntax for..."
- Have exactly **4 options** — one clearly correct, the others plausible but wrong
- Include an **explanation** that teaches, not just confirms — explain _why_ the answer is correct
- Have a **unique `id`** — check all existing IDs in both `lessons.tsx` and `quizQuestions.ts` before picking one

If you want your questions to also appear in the **Final Exam** tab, add them to `src/data/quizQuestions/quizQuestions.ts` as well (using the same objects, same IDs).

#### Step 6 — Verify quality gates

```bash
npm run test:coverage   # Must pass — 100% coverage, no regressions
npm run lint            # Must show 0 errors
npm run format:check    # Must pass — run `npm run format` to fix if needed
```

#### Step 7 — Commit and push

```bash
git add .
git commit -m "lesson(css): add CSS Grid lesson with interactive demo"
git push origin lesson/your-topic-name
```

#### Step 8 — Open the Pull Request

Go to GitHub and open a PR against `main`. Fill in the PR template completely. Incomplete PR descriptions will be asked to be revised before review begins.

### Lesson content guidelines

**`content` (the explanation):**

- Write as if explaining to a friend who has never coded before
- No jargon without definition — if you use a term, explain it in the same sentence
- 3–6 sentences is the right length — enough to give context, short enough to stay focused
- Do not copy text from MDN, W3Schools, or any other source — write it yourself

**`codeSnippet` (the code example):**

- Must be the simplest possible example that illustrates the concept
- No boilerplate, no imports — just the relevant lines
- Prefer HTML/CSS literals over JSX in snippets (they are displayed in a code block, not executed)
- Max ~10 lines

**Demo component:**

- Must be interactive — static examples belong in the `codeSnippet`, not the demo
- Must visually demonstrate the concept — someone should understand the concept by playing with it, even without reading the text
- Aim for simplicity: one control (slider, button, toggle) that reveals one insight

**Quiz questions:**

- Question 1 should test basic recognition ("which of these does X?")
- Question 2 should test application ("given this code, what happens?")
- Avoid trick questions — the goal is reinforcement, not gotchas

## PR checklist

Before marking your PR as ready for review, confirm every item:

### For all PRs

- [ ] I have read `CONTRIBUTING.md` in full
- [ ] My branch name follows the naming convention
- [ ] My commits follow the Conventional Commits format
- [ ] `npm run test:coverage` passes — no coverage regressions
- [ ] `npm run lint` reports 0 errors
- [ ] `npm run format:check` passes

### For lesson PRs (additional)

- [ ] I wrote all content and code myself — no AI tools were used
- [ ] The lesson teaches exactly one focused concept
- [ ] The `content` explanation is in plain English, written in my own words
- [ ] The `codeSnippet` is minimal and directly illustrates the concept
- [ ] The demo is interactive and visually demonstrates the concept
- [ ] The demo component is in `src/components/demos/YourTopicDemo/` with `index.ts` and a test file
- [ ] The demo is exported from `src/components/demos/index.ts`
- [ ] There are exactly 2 quiz questions in the `questions` array
- [ ] Each question has a unique `id` not used anywhere else
- [ ] Each question has exactly 4 options
- [ ] Each question has an `explanation` that teaches, not just confirms
- [ ] The PR description explains what concept is taught and why it belongs in the bootcamp
